# БРИГАДА

Небольшая браузерная база для производственной бригады. Работает без сервера и готова к публикации через GitHub Pages.

## Возможности

- каталог деталей: название, код, инструмент, станок, программа, ячейка и нулевые координаты;
- отдельный раздел станков и актуальных программ;
- поиск и фильтр по станкам;
- режим оператора: просмотр + изменение установленной пластинки;
- режим наладчика: добавление, редактирование и удаление деталей;
- учёт брака: деталь, код, дата, три вида брака и пояснение причины;
- редактирование и удаление записей брака;
- сохранение данных в `localStorage` браузера.
- вход пользователей через Firebase Authentication;
- общая синхронизация деталей, станков и брака через Cloud Firestore.

## Запуск

Откройте `index.html` в браузере. При первой загрузке база пустая: сначала добавьте станок, затем детали. Для публикации: загрузите файлы в репозиторий GitHub, затем в Settings -> Pages выберите Deploy from branch и ветку `main`.

## Firebase

Включите в Firebase Authentication способ входа **Email/Password** и создайте пользователей вручную в разделе **Authentication -> Users**. Правила из `firestore.rules` разрешают работу только авторизованным пользователям. После публикации добавьте домен GitHub Pages в **Authentication -> Settings -> Authorized domains**.

Для сотрудника с шестизначным кодом `482913` создайте пользователя с техническим email `482913@gezbrigada.local`. В приложении сотрудник вводит только `482913` и назначенный ему пароль. Администратор может продолжать входить своим обычным email.

Администратор видит вкладку **Пользователи**. В ней можно изменить имя, роль и доступ сотрудника или удалить его профиль. Пароли существующих пользователей изменяются через Firebase Authentication.

Конфигурация Firebase находится в `app.js` и содержит только публичные параметры Web-приложения. Пароли и service account keys в репозиторий не добавляются.

## Обновление: фото, задания и офлайн

- Роль «Бригадир» назначает администратор в разделе пользователей. Бригадир просматривает карты и управляет заданиями; наладчик также редактирует карты и фото.
- Фото добавляется кнопкой рядом с инструментом после выбора детали и станка. Сжатие до 1000 пикселей и менее 240 000 символов JPEG data URL. Фото хранится отдельным документом appData/photo-ID; в карте остаётся ссылка. Бесплатность зависит от общей квоты Firestore.
- Задания хранятся отдельно в appData/assignments, изменения выполняются транзакцией.
- Для офлайн нужно один раз открыть опубликованный HTTPS-сайт с интернетом и войти. После установки service worker оболочка доступна из кэша. Последняя база показывается сразу, обновления поступают из Firestore. Фото доступно офлайн после первого просмотра. Изменения без интернета заблокированы.
- Перед публикацией нужно применить firestore.rules в Firebase Console. Локальный файл правил сам по себе не изменяет серверные разрешения.
- Проверено: синтаксис JavaScript, целостность ссылок новых элементов интерфейса, отдельные ссылки на фото для разных станков и сохранение ссылок в редакторе. Полный браузерный прогон и проверка реального Firebase ещё не выполнены: браузер автоматизации не запускается в этой среде.
